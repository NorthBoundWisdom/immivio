# Architecture

## Application and interaction

`app/godot/scenes/main.tscn` and `scripts/main.gd` own application state. Godot OpenXR supplies tracking and the vendor-specific passthrough interface. GDScript menus use controller rays/triggers and hand pointing/pinching. Controller grip owns canvas movement/resizing, while an outside trigger tap toggles controls without dragging or pausing. The timeline is anchored to the canvas centre (content-forward in immersive projections), independently of head yaw; popups stay in the same canvas frame. By default, library and flat-playback menus remain vertical relative to world up. Library reset/open uses horizontal head direction; menu follow uses a yaw-only head frame. Flat video constrains its placement plane to world up on every pose application, while explicit picture rotation remains within that plane. Settings → General includes a persistent Reclining mode, off by default: it removes the flat-video tilt constraint and uses full head orientation for reset/open and menu follow. Enabling it immediately places active flat video in the current gaze; continuous Follow remains an independent session choice. Photo follow retains its full tracked pose. Immersive controls use the reset/content sphere basis, at 1.4 m forward and 0.28 m below its gaze centre, independently of later head tilt. Playback panels use 75% horizontal and 2/3 vertical scale, including their ray hit targets. Optical-hand content gestures retain their existing ownership. Libraries, settings, list popups and photo menus reserve thumbsticks for scrolling. The ordinary video control bar permits seek, volume and immersive zoom shortcuts. Pointer capture suppresses shortcuts; leaving a list or ending capture requires the stick to return to center before reactivation.

Display geometry separates flat/180°/360° projection from mono/SBS layout and eye order. Menu pages, per-file preferences and localization are independent of the Android media backend. The desktop path is a development preview and mock backend, not an equivalent Android/XR playback implementation.

The application includes persistent timestamp-only bookmarks (`bookmark_store`, `bookmark_menu`, `timeline_markers`), paged recent-file previews, cloud account/pagination handling, and input visuals. `input_visuals.gd` uses runtime render models when available and licensed glTF hand fallbacks. Seek keeps a presented frame until the target frame arrives; `seek_policy.gd` routes speed-first and precise positioning. No ratings, stars or bookmark editing are exposed.

Photo presentation uses immersive screen geometry, adjacent-image preloading and a separate stereo cache. Flat-photo navigation uses a single-hand horizontal pinch drag followed by release; two-hand pinch zoom remains available. Photo stereo strength supports 0–200%, independently of video strength. Selected ordinary flat photos can prepare depth and person matting, with matched color/mask updates before switching the presented pair. `projected_subtitles.gd` and the shader include implement subtitles in the video projection.

## Android boundary

`QuestPlayerPlugin.kt` exposes Godot-callable methods and owns Android media selection, libraries and lifecycle. Document grants, file descriptors and HTTP/SMB/cloud sources are managed in Kotlin. Authentication data stays in application-private storage; no account credentials belong in source control.

`LocalStoragePermissions` separates Android 10 legacy/read-permission access from Android 11+ all-files settings, with supported settings fallbacks and directory refresh. `DeviceBatteryStatus` interprets the sticky battery snapshot separately from cable connection; connected power alone does not mean charging.

The plugin contains older controlled MediaCodec/Media3 diagnostic paths. Normal video playback uses `MpvVideoBridge` and the native mpv source extension. Their presence in source does not mean that all paths execute during ordinary playback.

Account and server forms are rendered by `account_panel.gd` inside the VR library.
`AccountManager` owns transient authentication state and cancelled-request guards.
Web authentication uses `InAppWebLogin` to transfer in-memory WebView frames and
ray/keyboard events through the same host Activity. It does not launch account
Activities or the PICO 2D shell. Pause keeps the current workflow; an explicit
close cancels it. The global About page contains the license index and reader.
These bridges still require device-specific website/input validation.

## Rendering and inference

Android XR menus use a transparent 3072×2048 native quad composition layer when the Android Surface swapchain extension is supported. An unscaled UI-only orthographic camera renders the existing menu geometry in world metres, including anisotropic panel resizing on a reserved visibility layer; video geometry never enters that viewport. The main eye camera excludes those UI meshes only after native presentation succeeds; initialization or presentation failure keeps the scene fallback visible. Physical rays map through the compositor quad into the UI camera's space, preserving angled-column hit targets and slider ownership. The quad is an overlay above scene content; pointing rays stay in the scene and only reticles enter the overlay, avoiding a flattened laser stripe. Unsupported/desktop paths retain scene rendering. Menu fonts and their fallback use MSDF with mipmaps, and vector icons have mipmaps.

UI layout and compositor projection are presented together: the GPU bridge acknowledges each copied UI serial, and only then can its quad bounds/page pose be published. Pending pages cannot accept rays. Ordinary playback pages reserve one capture envelope up front, so first opening Settings or Playback does not expand/recentre the texture projection. Startup warms common icons and eleven synthetic UI pages in a disposable offscreen viewport; no media is opened and no image is read back.

The UI swapchain stays fixed in size and registered while hidden. Two transparent clearing frames precede disabling hidden viewport updates; the quad then becomes subpixel-sized. The ordinary viewport texture is copied entirely on the GPU into the XR-owned Android Surface by `XrUiSurfaceBridge`, using the Godot render thread/context and restoring EGL surfaces, framebuffer bindings and scissor state. This avoids Godot GLES external render-target override ownership errors on session resume. The copy corrects ordinary Godot GLES viewport Y orientation; Oculus GLES additionally uses the runtime layer flip documented by the GodotVR Android Surface example. The bridge never releases the XR-owned Android Surface. Texture handles are refreshed for a new context or Surface, and hidden UI does not render or copy continuously. Capture uses no MSAA: distance-field glyphs and analytic surface edges provide texture coverage. Main-view MSAA is independent, with 4x for Enhanced flat screens and 2x for Enhanced immersive playback. Runtime diagnostics report layer readiness, capture size, draw calls, GPU copy count/errors and view-plane alignment. No runtime CPU UI-image readback is used.

`native/mpv/mpv_source.cpp` connects libmpv's source-frame extension to JNI. `native/render-bridge` owns GPU texture/buffer operations. Frame PTS, generations and fences prevent mismatching image/alpha, showing stale frames after seek, or reusing a texture before GPU ownership is released.

The model-free standard-libmpv build uses public render transactions and explicitly unverified source PTS. Ordinary playback borrows each immutable mpv RGBA texture instead of copying it into a second full-resolution bridge texture. Its producer lease survives display claims and thumbnail/pixel pins, and is released only after the last consumer draw through a GPU fence. No inference input planes are allocated by the Kotlin ordinary-playback path. This removes one RGBA read/write per displayed frame without changing source resolution, cadence or color conversion; it does not eliminate mpv's initial YUV-to-RGBA render. The Debug `borrow_color=false` switch retains the copy path for measurement.

Public playback-clock estimates can correct backwards after a keyframe seek, from the requested timestamp to the actual landing time. The display orders these ordinary transactions by generation and frame sequence, without waiting for their estimated timestamps to catch up. Only an explicit standard-libmpv, valid, non-inferred ticket receives that exception. Verified frame timestamps remain monotonic; inference gates reject playback-clock estimates entirely. Display clock corrections, rejected offers and the maximum gap between distinct owner-drawn transactions are reported separately.

The standard producer reuses allocated free textures before growing its seven-slot ring, and can recycle the oldest unclaimed ready texture when another ready image remains available. Acquired/retiring textures stay protected, and the newest ready image remains available during replacement. This limits idle 8K allocations without shrinking the maximum number of overlapping consumer leases. Producer RGBA allocation bytes and bridge RGBA allocation bytes are reported separately.

For borrowed opaque playback, a slot with an already initialized opaque mask needs no GPU capture work. After acquiring the completed producer fence, the bridge can hand off the immutable color and cached mask without saving/restoring GL state or adding a capture fence. Kotlin offers an immediately ready pair in the same owner draw. Producer leases, pixel/thumbnail pins and consumer retirement fences still protect every texture. Copy, inference and uncached-mask paths retain their GL state guard and capture fence.

Ordinary non-packed RGBA video also uses an opaque Godot material, avoiding transparent blending and allowing depth rejection of background geometry. It preserves the existing eye coordinates, sharpening, grading and subtitle composition. Packed alpha, inferred alpha/depth, warped pairs and external decoder textures retain their dedicated shaders. Inference input PBOs are allocated on first input staging rather than at every bridge creation; ordinary playback never needs them.

The standard producer allows at most two GPU-incomplete ready renders by default and only replaces ready storage after its producer fence signals. When storage is unavailable, ordinary playing frames may be skipped; paused redraws, seek results and the final frame remain pending for retry. Debug `debug.vrpp.mpv.gpu_frames=0` restores unbounded submission for comparison. This bounds queued producer work, not the number of decoded frames or all GPU work in the application.

At standard-libmpv EOF, the producer drains queued video frames before resolving one retained render transaction. `REDRAW` implies `PRESENT` in the public API but does not represent a new video image. Terminal classification is checked again after slot/GPU backpressure. Once the final transaction is published, routine keep-open callbacks cannot replace its identity; update callbacks are still serviced and keep-open redraw requests acknowledged without GPU output, while explicit redraws or a seek can resume rendering. Completion still requires the matching pair to be observed after an owner draw, rather than trusting the core EOF flag alone.

Bridge entry points record pre-existing shared-context GL errors separately before checking their own operations; context loss remains fatal. Diagnostics expose those errors, state-save/bypass counts, producer render-call time and capture-to-ready time. These are CPU wall-clock measurements, including possible driver waits, rather than GPU timestamps or end-to-end display latency.

Source diagnostics also expose session-relative timestamps for seek submission, the first seek event, playback restart and the first render in the new epoch. A newly bound seek frame and resumed continuous playback are separate milestones; measure both before attributing seek latency to storage or decoding.

The standard renderer waits for the core's `SEEK` event before accepting a new-epoch `PRESENT` frame. Submitting the public seek command only queues core work: a previously queued old frame may still have `PRESENT` without `REDRAW`. A restart queued before the seek event cannot release this gate. Update callbacks remain serviced while waiting, and the first new frame may render before the matching playback restart.

Routine mpv logging is `warn` in Release and `info` in Debug. Per-read/per-seek debug messages otherwise flood Android logcat on non-interleaved MP4s. For a bounded Debug investigation, `adb shell setprop debug.vrpp.mpv.log debug` restores verbose playback logging; clear that property afterwards. Decoder selection/fallback remains visible in Debug and in playback status.

The normal matting backend uses MNN OpenCL with four recurrent states for each eye. ROI decisions are in Kotlin's `RoiController`; the default source snapshot uses the internal 320×320 fast profile. No model/resolution selector is exposed in the normal UI. ncnn/reference paths are retained for dedicated diagnostics; normal playback has no automatic CPU fallback.

The independent depth backend processes flat mono videos/photos using Depth Anything V2 Small. `depth_stabilizer` limits temporal variation before Godot renders depth-based stereo. Depth updates and display frames have distinct timing; a rendered-frame rate is not an inference rate.

Model selection is a build input, independent of the media session and frame gates. A versioned `ai-models/manifest.json` maps matting, video depth and photo depth to their adapter contracts. `tools/model_assets.py` verifies complete source packs before importing; `ModelRepository` validates the installed contract and verifies model bytes lazily on a worker. Public upstream and private/distilled weights keep separate identities and hashes while using the same compatible adapters. `MattingRuntime` is the session interface used by the video effect queue; MNN remains the only production inference engine in this phase. Fixed adapter asset paths are normalized during import. Runtime model downloads and hot switching are not implemented. See [model packs](MODELS.md#model-pack-and-adapter-boundaries).

## Build boundaries

The Godot export plugin references the separately built Kotlin AAR and Maven dependencies. The matching Godot template provides one engine. Each Android export preset enables one vendor loader. Models, SDK/addon binaries and native libraries are prepared outside Git and checked during packaging.

The public snapshot removes private store-capture automation from the application startup path. It retains runtime icons, the licensed background, synthetic fixtures and production behavior. Source-only tests do not establish headset passthrough quality, tracking or sustained thermal performance.

## Cloud providers

Existing 115 and Baidu clients retain encrypted account records. The embedded OpenList JNI core supplies additional provider connections, including 115 Open, OneDrive, Aliyun Drive and Quark. Only the capability-protected loopback media router listens on HTTP. Authorization stays in the same Activity's VR web panel; provider-specific callbacks are validated against the active session/state before importing credentials and checking directory access. Quark uses the FnNAS broker's nonce-bound callback exchange. No OpenList frontend or separate Android account window is used. Real-account and minimum-headset validation remains separate from source publication.

Media-server browsing separates home sections, loaded pages, filter/category state and detail navigation. Favorites use server support where available and a local fallback otherwise. Source policies and native/Go bridges provide supported rename/delete operations without assuming every backend permits writes. Photo magnification maps the displayed image's local projected size to a separate inspection window; it does not enlarge the underlying full-image shader.
