# Contributing

Use [NorthBoundWisdom/immivio](https://github.com/NorthBoundWisdom/immivio) for this independently maintained edition. Open an issue or pull request with a concrete problem, the affected source path and a reproducible example. Keep one change focused on one behavior. Contributions to project-owned source are submitted under GPL-3.0-only; preserve existing third-party notices and identify any imported code's origin/license.

Run the source boundary and applicable host tests described in [TESTING.md](docs/TESTING.md). Android changes also need JVM/build checks; headset-specific claims need device evidence with matching versions. State what you have and have not verified.

Format project-owned, Git-tracked code using the root configuration files. Use Black for Python, gdformat for GDScript, ktfmt with `--kotlinlang-style --do-not-remove-unused-imports` for Kotlin, google-java-format with `--aosp --skip-sorting-imports --skip-removing-unused-imports` for Java, clang-format for C++ and Godot shaders, cmake-format for CMake, Prettier for HTML/CSS/JavaScript/JSON/YAML (plus `@prettier/plugin-xml` for Android manifests), Groovy-Eclipse with `.groovy-format.properties` for Gradle scripts. Keep a trailing comma after multiline lambda arguments in GDScript so Godot accepts the indentation. Preserve vendored code (including `native/mpv/include/mpv/`), generated assets, lockfiles and dependency/build directories. Formatting must preserve behavior and pass `git diff --check` and the applicable host tests.

For maintainer Android/XR fixes, install the build on the target headset and obtain the owner's device acceptance before pushing the changes or a release tag. Keep local verification focused on the affected device; other build hosts are covered by CI.

Immivio is an independent personal open-source project, unrelated to the maintainer's company. Do not use employer or other company signing keys, credentials, organization fields or branding for Immivio. Keep its project-local signing identity separate; the retained legacy certificate is `CN=Thru3D` without a company organization field, and newly provisioned keys use `CN=Immivio`. Referencing another repository's Android configuration does not authorize copying its signing material.

Do not commit model weights, generated APKs/libraries, signing material, credentials, personal media or device logs containing user data. Provide synthetic reproduction fixtures or generation instructions. Do not send account tokens in public issues.

VR menus use controller ray/trigger selection or hand interaction, never thumbstick selection. Libraries, settings and list popups reserve thumbsticks for scrolling and suppress playback shortcuts. The ordinary video control bar allows the same seek and immersive zoom shortcuts as hidden controls. Pointer capture suppresses shortcuts; after leaving a list or ending capture, the stick must return to center before reactivation. Keep visible UI text concise and place implementation notes in technical documentation.

Distribution APK filenames use platform names `QUEST`, `PICO` and `OpenXR`, with the requested software version and build date. Do not use specific headset models in distribution filenames.

For every version update, maintain `CHANGELOG.md` and the matching English/Chinese release notes in `website/updates/` and `website/zh/updates/`. The bilingual website owns translated user documentation; the repository keeps one README and one technical changelog. Review the README feature overview: add important durable capabilities, while keeping fixes and detailed history in the changelog. Preserve media/device limitations and use English commit messages.

The user website lives in `website/`, with an English home, guide and release notes, and matching pages under `website/zh/`. Run `python3 tools/check_website.py` and `node --check website/assets/site.js` after editing it. The Pages workflow publishes this directory from `main` and refreshes the APK selector when a GitHub Release is published. Keep actual screenshots and their capture manifest together; do not commit the source video or device diagnostics.

Keep search titles, descriptions, social previews and JSON-LD consistent with each page's visible content in both languages. Update sitemap modification dates only for pages whose content changed. Performance claims need evidence; describe supported hardware decoding and GPU rendering without inventing benchmarks, ratings or format guarantees. Keep the repository description and topics aligned with the README's current product scope.

The supplied application artwork is `app/godot/branding/immivio-icon.png`. After replacing it, run `godot --headless --xr-mode off --path app/godot --script ../../tools/prepare_branding.gd` for adaptive safe-area sizing and the website icon. The script uses the supplied transparent layers under `branding/source/` for adaptive/themed icons and prepares website posters and PICO portal assets. Keep all six original sources and their checksums in `branding/source-manifest.json`; Android monochrome and background assets are generated PNGs. All three Android export presets share these assets.

Generated outputs must follow `configs/output_paths.py` and the layout in `docs/BUILD.md`: installable packages under `artifacts/packages/`, test results under `artifacts/tests/`, captures under `artifacts/captures/`, and logs under `artifacts/logs/`. Put temporary scripts, extracted libraries and test inputs under the appropriate `build/` category. Do not create ad hoc files directly in either output root. Use the workflow `organize`, `locate` and scoped `clean` commands. Never store signing material in either output root.
