IMMIVIO / UPDATES

What’s changing in Immivio.

These notes describe the v0.9.3 source milestone. Check the notes attached to your APK for the features in that build.

Development / Unreleased

  • Use the independent Immivio Android identity and video-app classification. Legacy installations remain separate; data is not migrated automatically.
  • Fix simultaneous native library/toolbar display and pointer routing, cinema preset selection and logarithmic distance adjustment.
  • STRM shortcuts for existing local and network media, with readable loading stages and playback errors.
  • Remembered folder positions, per-folder sorting, list/icon views and compact browsing while playback controls stay available.
  • Spatially locked controls, adjustable bar opacity and flat-screen cinema presets with fixed viewing defaults.

These changes are in development source. Check the notes for your APK; headset acceptance is still required.

v0.9.3 — October 14, 2026

  • Reset grading, subtitle, timing, eye-alignment and photo sliders directly in their existing popups. A grading page reset affects only its three controls; Reset custom restores the complete custom look.
  • Keep Original, Warm, Cool and Custom colour presets. Existing Daylight selections return to Original while preserving saved custom adjustments.
  • Improve Windows and macOS build reliability and simplify playback dependencies. All headset packages use the same verified Android mpv/FFmpeg playback implementation.
  • Strengthen regression checks for playback controls, video geometry, downloads and thumbnail capture. Headless tests must finish explicitly and use separate saved settings and caches.

Verified APKs are attached to this release automatically after both release build hosts complete their checks.

v0.9.2 — October 14, 2026

  • Use one compact playback toolbar with individual popups for subtitles, speed, grading, eye alignment, timing, queues and source information.
  • Place the filename beside the battery and clock, shorten long names in the middle, keep Close separate and centre previous/play/next. Controls sit 20% closer with a lower timeline and less empty space.
  • Advance automatically after the final frame and return to the file browser at queue end. Remove loop, add-bookmark and seek-method controls; existing bookmarks remain available.
  • Follow system volume. Remove application volume, audio-track, frame-rate, screen-rotation and recenter buttons from the playback toolbar.
  • Apply Home recentering once after updated tracking arrives in the same frame. Keep the window at its remembered horizontal distance without hiding it.
  • Update the About repository link and remove the contact email.

Local host, JVM, Go, workflow, release and website regressions passed. The PICO build was installed on the physical headset. Tags now create a Release automatically; verified APKs are attached after both Android build hosts pass.

v0.9.1 — October 13, 2026

  • Keep PICO windows fixed when the runtime emits automatic tracking-space reset notifications. Use in-app recenter when you want to move content back in front of you.
  • Remove the low-frame-rate fallback that permanently disabled supported native menu layers. Retain high-resolution native UI and MSDF text rendering.
  • Centre the complete file-browser window on the current gaze when opening or explicitly recentering it. Keep your upright/reclining preference and leave the placed window fixed unless Follow is enabled.

The fixes were verified on a physical PICO 4: stable windows, clear menu text and comfortable file-browser placement. Other build hosts are checked by CI. Published APKs appear after the tag build succeeds.

v0.9.0 — October 13, 2026

  • One media player for existing stereo and spatial content. Live AI depth, person matting and model-based photo conversion have been retired.
  • Remember explicit audio and subtitle choices per video, volume and mute across launches. Double-tap the volume icon to mute or restore sound.
  • Choose from five text-subtitle palettes and adjust audio/subtitle timing independently. Saved queues support repeat, shuffle and automatic advance.
  • Arrange photo walls in 1–3 rows, retain per-video eye alignment and read long library filenames in expanded hover tips.
  • Keep DLNA subtitles when metadata is incomplete, and recover the library position when closing a video.
  • Refactor playback frame validation and resource ownership, remove retired inference buffers, and split application controllers for continued maintenance.
  • Simplify dependency management with FreeCM and preinstalled development tools and verified Android playback libraries.

This milestone completed the playback refactor and dependency-management simplification, with local regression and Android packaging checks. See v0.9.1 above for the subsequent PICO device fixes.

Choose the package for your headset.

Use the Quest or PICO APK for those devices. Generic OpenXR is experimental and needs a compatible Android runtime. Source ZIP/TAR archives are for developers.

Text subtitles and packed SBS/TB video use the same playback pipeline in all packages. Bitmap subtitle tracks are not offered. MV-HEVC dual-view video and Dolby Vision colour correctness have not been validated; file names alone do not establish support.

Updates need a matching Android application identity and signing key. Packages signed by another distributor or temporary CI keys may require a separate installation.

Immivio has no 2D-to-3D conversion or person-matting edition. Historical releases may describe features that have since been removed.

History and source changes

Immivio continues independently from the original 0.6.0 baseline. Published releases carry their own package notes; the source changelog retains earlier milestones.

Developer setup now uses preinstalled host tools and Android media libraries. FreeCM manages OpenList sources and the OpenXR addon. See building from source.
